# Release Machinery Implementation Plan

**Goal:** A `buildl-cli-v*` tag pushed at a green commit produces a GitHub release whose six
`buildl` archives were each smoke-tested on their own platform before publishing.

**Architecture:** cargo-dist 0.33.1 owns the release. `dist-workspace.toml` is its whole
configuration, and `.github/workflows/buildl-cli-release.yml` is `dist generate`'s output, never
edited by hand. The one hand-written workflow, `buildl-cli-smoke.yml`, is hooked in through
`global-artifacts-jobs`, and it runs a toolchain-free buildl workspace kept under `.github/smoke/`.
The crate-facing pieces the publish needs (`CHANGELOG.md`, `homepage`, the `buildl-cli` README, a
`publish-dry-run` task) land in the same pull request, PR A, which touches nothing under `book/`
or `install/`, so merging it does not deploy Pages.

**Tech Stack:** cargo-dist 0.33.1, GitHub Actions, POSIX `sh`, cargo-make, Keep a Changelog.

**Content authority:** spec sections 3, 4 and 6 (the rows `CHANGELOG.md`, `Cargo.toml`,
`crates/*/Cargo.toml`, `Makefile.toml`, `crates/buildl-cli/README.md`), and section 7 steps 1-2.

## Order of work

### Task 1 — Add the smoke workspace

**Files:**
- Create `.github/smoke/buildl.toml` — `[workspace]` with `name = "smoke"`, `entry = "build.lua"`,
  `out = "out"`, `config = 1`; `[ceiling]` with `proc.run = ["sh"]`, `fs.read = ["."]`,

  `sh -c` with `tr a-z A-Z` into `$out`; `buildl.test("reads", …)` reading `greeting.txt` and
  running `sh -c` with `grep -q hello`
- Create `.github/smoke/greeting.txt` — the line `hello`
- Modify `.gitignore` — add `.github/smoke/out/` and `.github/smoke/.buildl/` beside the existing
  `examples/*/out/` and `examples/*/.buildl/` entries, since a smoke run writes both

**Change:** a buildl workspace that exercises build, the input sandbox, the cache, tests and
`verify` with nothing but `sh`, `tr` and `grep`, so the smoke workflow can run it on every runner
and inside Alpine. Its shape is the one spec section 4 proved.

**Proof:** written first, seen failing (no workspace), then passing, with this checkout's
`cargo build -p buildl-cli` binary, from `.github/smoke/` under `env -i HOME="$HOME" PATH=/usr/bin:/bin`,
after removing `out` and `.buildl`:

**Done when:** the five checks pass, `git status` shows no untracked build output, and
`cargo make dod` is green. Commit `ci(repo): add a toolchain-free smoke workspace`.

### Task 2 — Write the smoke workflow

**Files:**
- Create `.github/workflows/buildl-cli-smoke.yml`

**Change:** a reusable workflow, `on: workflow_call` with a required string input `plan`, in the
shape of airsl's `.github/workflows/airsl-cli-smoke.yml` (spec section 2) with Windows removed:
- job `targets` (`ubuntu-22.04`): derives the matrix from the plan's `executable-zip` artifacts
  joined with a fixed target→runner table: `aarch64-apple-darwin` → `macos-14`,
  `x86_64-apple-darwin` → `macos-15-intel`, `x86_64-unknown-linux-gnu` → `ubuntu-22.04`,
  `aarch64-unknown-linux-gnu` → `ubuntu-22.04-arm`, `x86_64-unknown-linux-musl` → `ubuntu-22.04`
  with `alpine: true`, `aarch64-unknown-linux-musl` → `ubuntu-22.04-arm` with `alpine: true`; fails
  when the plan lists no archive or an archive has no runner; outputs the matrix and the plan's
  `releases[0].app_version`;
- job `smoke` (per archive, `fail-fast: false`, `contents: read`): checkout without persisted
  credentials; download `artifacts-build-local-*` with `merge-multiple`; check the archive against
  its `.sha256` (`sha256sum -c`, or `shasum -a 256 -c`); unpack the `.tar.xz`; set `BUILDL` to the
  binary, or for `alpine: true` to a wrapper running it through
  `docker run --rm -v "$PWD:$PWD" -w "$PWD" alpine:3.20`; then the checks below.

Checks, each a named step:
- `--version` prints exactly `buildl <app_version>`;
- in `.github/smoke/`: `build`, `test`, `build` again and `verify`, each exiting 0, with the
  second build printing `1 cached`;
- in each of `examples/go`, `examples/go-discovery`, `examples/plugins`, `examples/polyglot`,
  `examples/python`, `examples/rust` and `examples/remote`: `check` and `doctor` exiting 0.

**Proof:** the workflow runs only inside the release workflow, so its proof is Task 6's PR run.
Locally:
- `smoke workflow parses` — `python3 -I -c` loading the file with a YAML parser succeeds, or
  `actionlint` on the file reports nothing when it is installed; where neither is available,
  `ruby -ryaml -e 'YAML.load_file(ARGV[0])'` on the file succeeds
- `smoke runner table covers dist` — the six triples in the table are exactly the `targets` row
  of spec section 3 (Task 3 then writes the same six into `dist-workspace.toml`)

**Done when:** both checks pass and `cargo make dod` is green. Commit
`ci(repo): smoke-test every release archive on its own platform`.

## Risks

- **The musl builds are the riskiest step (Task 6).** buildl's CI has never built
  `*-unknown-linux-musl`; `ring` (through `tonic`'s `tls-ring`) and the vendored Lua must compile
  with `musl-gcc`, and the sandbox must run on busybox inside Alpine. The PR run is where this is
  first proven, by the author's choice at design, and nothing is published before it passes.
- **`dist init` may write more than the spec's keys** (for example the `release.yml` name, or
  `install-path = "CARGO_HOME"`, as it did on the design probe). Task 3 sets every key explicitly
  and deletes the stray workflow, and its proofs catch a leftover.
- **The generated workflow drifts if hand-edited.** The plan never edits it; a change goes through
  `dist-workspace.toml` and `dist generate`.
- **Every pull request now builds six release archives.** That is airsl's choice too
  (`pr-run-mode = "upload"`), and it is what proves the targets before a tag; it costs CI time on
  every PR.
- Not done here: the install pointer, Pages, the root README, the book and `skills/install.sh`
  (plan 03), and the publish itself (plan 02).

# The `buildl` Binary Implementation Plan

**Goal:** `crates/buildl-cli` becomes the `buildl` binary that runs `check`, `graph`, `plan` and `build` on a real workspace and ends with the exit status of spec §9.3.

**Architecture:** `main.rs` reads the process's facts (arguments, current directory, whether stderr is a terminal, `TERM`, `NO_COLOR`) and hands them to `run::run`, which holds the whole flow over values and two writers. `cli.rs` is the clap surface; `exit.rs` maps every `OutcomeClass` and every `Error` variant to a code by one structural `match` each; `terminal.rs` decides `Mode` and `Paint`. Every rendering is `buildl::report`'s; core types come through `buildl::buildl_core`. The binary depends on `buildl` and `clap` only (dev: `tempfile`).

**Tech Stack:** Rust 2024, rustc 1.94 floor; clap 4.6.7 (`default-features = false`, `std derive help usage error-context suggestions`); tempfile 3.27.0 (dev); system tools `cp`, `false`, `true`, `sh`, `sleep`, `/bin/cat`, `/bin/cp`, `/bin/ln` in tests; cargo-make, cargo-deny.

**Content authority:** spec §9 (all), §11, §12.5, §13.3 and §13.4 (the `buildl-cli` lines), §14 (`clap`, dev `tempfile`), §15.4 (`crates/buildl-cli/src/main.rs` rustdoc), §17.

**How this plan is landed.** The code is not written out here: it was built and gated task by task in the scratch tree (`proto/11`, with each task's state kept under `proto/11-plan/steps/tNN`) and is copied into the repository from there. Each task below is one commit; after every task `cargo fmt --all -- --check`, `cargo make dod` and `cargo make deny` exit 0.

Why this order: in a binary crate an item nothing reachable from `main` uses is dead code and fails clippy, so every type, variant and field arrives with its first caller (`Exit::ActionFailure` with `build`, `Stop::Usage` with `plan`, `Color` with the terminal). Tasks 2–6 each start with failing unit tests (unresolved imports); tasks 8–10 characterise behaviour tasks 2–6 built, through the real binary.
